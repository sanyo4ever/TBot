# TBot 3.4.6b

Console maintenance release on our [3.4.6a](https://github.com/sanyo4ever/TBot/releases/tag/3.4.6a) base. The author release remains 3.4.6; the letter records our independently reviewed maintenance revision.

## Included changes

- Espionage reports accept explicit zero counts consistently while rejecting positive or invalid negative threats and incomplete fleet/defence information. Existing probe-specific target policy is retained.
- Brain workers retain replacement celestial snapshots, calculate shipment capacity with the actual sending origin's lifeform cargo bonuses, and reset lifeform limits for each planet.
- Single lifeform discovery uses the current galaxy page token and explicit mission eligibility. Both the Go action and C# HTTP boundary send the action at most once per call, including lost responses and HTTP errors. Application success must be explicit; redirects require separate, strict fleet evidence before they can count as success.
- Settings paths share a synchronized lock after normalization. Reload failures release the gate and retain ownership of completed startups. Failed initialization cleans up through its DI scope; failed cleanup blocks a replacement for that settings path. Repeated Ctrl+C signals initiate graceful shutdown without throwing.

All 3.4.6a fixes, including strict OGame 13 target validation, are retained. No production dependency or configuration-format change is required.

## Sources and scope

We audited the actual release branches of [Ronnie's v3.5.1-beta2](https://github.com/ronnie32/TBot/releases/tag/v3.5.1-beta2), [Raphael's v3.5.0-beta11](https://github.com/Outgrow1827/TBot/releases/tag/v3.5.0-beta11), and [Whatsupp's v4.0-beta14](https://github.com/nemiel1972-lang/tbot4.0-beta/releases/tag/v4.0-beta14). Small C# fixes were implemented in our existing architecture with independent regression tests. Discovery adaptations retain the Go MIT attribution and exact donor commits in `ogame/doc/discovery-protocol.md`.

This release does not import their UI, updater, bulk discovery, farming ledger, new fleet-management policies or PoW/login implementations. Those need separate design and verification. Our C# no-replay change is limited to single discovery; it is not a universal idempotency guarantee for every fleet endpoint.

## Verification and limits

Validation of the combined changes: **283 C# cases, 767 Go test/subtest records (572 top-level tests across 20 tested packages), and 9 version-policy tests passed**. No test failed or was skipped; another 10 Go packages contain no tests. `go build ./...` and workflow lint passed. Independent reviews reproduced and then verified the repaired partial-initialization, cleanup-failure and incomplete-discovery-evidence cases.

Regression tests run with synthetic protocol fixtures, fake services and temporary local files. They do not log into OGame, send a real fleet or contact Telegram. Source-based fixtures cannot certify compatibility with every current live server response. An indistinguishable concurrent manual discovery on the same route cannot be uniquely attributed without a server request ID.

Discovery requires a complete, successful movement snapshot before sending. A redirected movement read remains unconfirmed; historical redirects to an empty `fleet1` page are not used as proof. Fleet records without an explicit outgoing direction and origin/destination types can be included in the earlier ID watermark, but cannot prove a newly sent discovery. Cleanup failures require attention/restart before replacement; shutdown waits for an in-progress settings reload rather than abandoning its startups.

The release workflow tests C# and Go again and requires all seven platform packages to build before creating a draft. Every ZIP contains `BUILD-INFO.txt` with exact TBot and Go commits; `SHA256SUMS` covers all packages. Existing compiler and dependency warnings remain visible in CI logs.

For a local upgrade, retain the previous folder, copy private settings and profiles privately, stop the previous client, then start this version. Do not run two clients for the same account simultaneously.
